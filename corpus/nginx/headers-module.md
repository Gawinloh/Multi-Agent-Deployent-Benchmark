# nginx HTTP Headers Module Reference

The `ngx_http_headers_module` provides the `add_header` directive for appending custom HTTP response headers. This is the primary mechanism for setting security-related headers that instruct browsers to enforce protective behaviours.

## Critical Inheritance Behaviour

A key characteristic of `add_header` in nginx is that directives defined in a parent context (such as `server`) are **not inherited** by a child context (such as `location`) if that child block defines any `add_header` directives of its own. When a nested block includes even one `add_header`, all parent-level headers are dropped for responses matched by that block.

To ensure headers are applied even when the response is generated by an error or redirect, append the `always` flag. Without `always`, headers are only added to successful responses (2xx and 3xx status codes).

## Recommended Security Headers

### X-Frame-Options

Prevents the page from being embedded in frames or iframes on other sites, mitigating clickjacking attacks. The value `SAMEORIGIN` allows framing only from the same origin.

```nginx
add_header X-Frame-Options "SAMEORIGIN" always;
```

### X-Content-Type-Options

Prevents browsers from MIME-sniffing a response away from the declared content type. This stops attacks where a malicious file is disguised as a benign type.

```nginx
add_header X-Content-Type-Options "nosniff" always;
```

### X-XSS-Protection

Activates the built-in cross-site scripting filter in older browsers. The `mode=block` directive tells the browser to block the page entirely rather than attempting to sanitise the content. Note that modern browsers have deprecated this header in favour of Content Security Policy, but it remains useful for legacy client support.

```nginx
add_header X-XSS-Protection "1; mode=block" always;
```

### Strict-Transport-Security (HSTS)

Instructs browsers to access the site only over HTTPS for the specified duration. A `max-age` of 31536000 seconds (one year) is a common production value. The `includeSubDomains` directive extends the policy to all subdomains.

```nginx
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```

Only enable HSTS when HTTPS is fully deployed and tested, as it cannot be easily reversed for clients that have cached the policy.

### Referrer-Policy

Controls how much referrer information the browser sends when navigating away from the site. The `strict-origin-when-cross-origin` value sends the full URL for same-origin requests but only the origin (scheme + host) for cross-origin requests, and sends nothing when downgrading from HTTPS to HTTP.

```nginx
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
```

### Content-Security-Policy (CSP)

Defines an allowlist of content sources, providing strong mitigation against cross-site scripting and data injection attacks. CSP policies vary significantly per application and should be carefully tailored. A minimal starting point:

```nginx
add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self';" always;
```

CSP is the most complex security header to configure correctly. Overly restrictive policies break application functionality; overly permissive ones provide little protection.

## Combined Configuration Example

```nginx
server {
    # Security headers - define in the server block
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Content-Security-Policy "default-src 'self';" always;
}
```

## Provisioning Notes

- Because child blocks override parent headers entirely, a common pattern is to define all security headers in an included snippet file and `include` it in every `location` block that adds its own headers.
- Always use the `always` flag to ensure security headers are present on error responses as well.
- HSTS should only be enabled after confirming that all resources, including subdomains if `includeSubDomains` is used, are fully accessible over HTTPS.
- Content-Security-Policy requires per-application tuning and should be tested in report-only mode (`Content-Security-Policy-Report-Only`) before enforcement.
